# Integration Architecture: Bakta, EggNOG, and InterProScan

This documentation details the computational and biological logic governing the integration of external functional annotations (EggNOG-mapper, InterProScan) into a baseline GenBank (`.gbff`) file generated by Bakta. 

The pipeline employs a **Hierarchical Symbiosis Model**. It respects Bakta's structural coordinates, prioritizes EggNOG for whole-molecule evolutionary history (orthology), and utilizes InterPro for high-resolution structural domain mapping. The logic guarantees a mathematically non-redundant, maximally deep functional ontology without creating biological contradictions.

## 1. Database Authority and Hierarchy

The integration strictly follows an established authority hierarchy depending on the biological data type being resolved.

| Data Type | GenBank Field | Primary Authority | Secondary Fallback | Tertiary Fallback | Scientific Rationale |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Gene Symbol** | `/gene` | Bakta | EggNOG | InterPro (Tier 1)* | Gene symbols reflect evolutionary orthology, maximizing EggNOG's primary strength. |
| **Protein Name** | `/product` | Bakta | EggNOG | InterPro (All Tiers) | EggNOG predicts whole-machine function; InterPro identifies localized structural components. |
| **Ontology** | `db_xref="GO:..."` | Maximal Specificity Algorithm | | | Prevents semantic redundancy while capturing multi-domain pleiotropy. |
| **Tracking IDs** | `/db_xref` | Symbiotic Addition | | | Zero scientific conflict exists between different database namespace tracking IDs. |

*\*InterPro gene names are typically left blank by the parser to prevent structural signature IDs (e.g., `PF00270`) from incorrectly populating the gene field.*

## 2. Nomenclature Resolution (`/product` and `/gene`)

The pipeline operates on a strict "graceful enhancement" protocol. It never blindly overwrites confident baseline annotations.

* **Baseline Preservation:** If Bakta has assigned a confident product name (not `"hypothetical protein"`), the script preserves it.
* **EggNOG Name Evaluation:** For hypothetical proteins, EggNOG acts as the primary naming authority.
    * **Junk Filter:** EggNOG outputs are checked against a blacklist (`"nan"`, `""`, `"hypothetical protein"`, `"uncharacterized protein"`). Matches are discarded.
    * **Overflow Protection:** If a valid EggNOG name exceeds 50 characters, it is diverted to the `/note` field to prevent downstream GenBank viewer rendering errors.
* **InterPro Fallback:** If EggNOG fails to provide a valid name, the pipeline extracts the name from the InterPro dataset. The InterPro parser provides either a Tier 1 whole-protein name (e.g., TIGRFAM) or a concatenated list of Tier 2 domains (e.g., `"DEAD box helicase; RecG wedge"`).

## 3. Ontology Resolution: The Maximal Specificity Algorithm

To prevent false precision and database bloat, the pipeline subjects all Gene Ontology (GO) terms to semantic analysis using the `goatools` OBO topological graph. 

EggNOG GO terms establish the evolutionary baseline. Every InterPro GO term is evaluated sequentially against the EggNOG baseline using structural topology rules:

1. **Exact Match (Discard):** The InterPro term is identical to an EggNOG term. The duplicate is destroyed.
2. **InterPro is Parent (Discard):** The InterPro term (e.g., "Kinase") is an ancestor of the EggNOG term (e.g., "Tyrosine Kinase"). EggNOG is already more specific; the InterPro term is discarded to prevent topological bloat.
3. **InterPro is Child (Keep):** The InterPro term represents a specific structural pocket (Child) that EggNOG only recognized broadly (Parent). The InterPro term is integrated to increase the functional resolution of the feature.
4. **Completely Unrelated (Keep + Bridge Note):** The InterPro term and EggNOG term sit on completely distinct topological branches. This scientifically indicates a multi-domain protein. The term is kept, and the action triggers a contextual explanation.

## 4. Metadata and Cross-References (`/db_xref` and `/note`)

The pipeline ensures all downstream systems biology tools have access to complete tracking data.

* **Symbiotic Database Linkage (`/db_xref`):** The script systematically extracts and deduplicates all machine-readable namespace identifiers. It integrates:
    * **EggNOG:** COG orthology clusters, KEGG pathway identifiers, and EC numbers.
    * **InterPro:** IPR structural signature identifiers.
    * **GO:** The finalized, deduplicated list outputted by the Maximal Specificity Algorithm.
* **Contextual Bridge Notes (`/note`):** When the Maximal Specificity Algorithm identifies completely unrelated GO terms (Rule 4), the pipeline actively prevents biological misinterpretation by inserting a bridging note into the GenBank file: `/note="InterPro detected additional domain/function: [InterPro Description]"`.
* **PFAM Domains:** EggNOG's PFAM domain predictions are safely stored as text inside the `/note` field (`Eggnog PFAM comment: PFXXXXX`).

## 5. Evolutionary Remnant Processing (Pseudogenes)

If a secondary GFF3 file denoting computationally predicted pseudogenes is provided, the script maps these coordinates back to the baseline. If the target locus remains annotated as a `"hypothetical protein"`, the script assigns a specific `/pseudogene="[description]"` qualifier. This flags the feature as a non-functional evolutionary remnant, actively removing it from downstream active pathway analyses.
